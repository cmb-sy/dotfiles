# HTML View — 使い捨て HTML で見せる

ターミナルのテキストでは読みにくい情報を、ローカルの HTML ファイルとしてブラウザに出す。同じ話題の情報が更新されたら、**新しいページを作らず同じページを同じタブで更新する**。

## 発動条件

**明示的に頼まれたときだけ使う。** 長い出力を勝手に HTML 化しない。

| 使う | 使わない |
|---|---|
| 「HTML で見せて」「ブラウザで見たい」「見やすくして」 | 頼まれていない通常の応答 |
| 「さっきの◯◯を更新して」（既存ページを指して） | 恒久的に残す学習教材 → `learn` |
| 既存スキルの長い出力を渡されて可視化を頼まれた | 検証付きの技術メモ → `tech-memo` |
| 表・スコア・一覧・比較で、ターミナルだと折り返しが崩れるもの | 非エンジニア向けの報告文 → `share-report` |

判断に迷ったら作らない。ユーザーは必要なら明示的に頼む。

## 対象の確定（最初に行う）

**何を HTML にするかが依頼文だけで確定しないなら、`AskUserQuestion` で選ばせる。** 推測で作り始めない。

`header` は `対象`、選択肢は 2 つ。

| 選択肢 | 意味 |
|---|---|
| 直前のやり取りをそのまま | 直前に会話で出した内容（表・分析・調査結果）を、そのまま HTML にする |
| 直前を踏まえて別の切り口で | 直前のやり取りを土台に、これから指定する観点で作り直す |

**ラベルと `description` には直前の話題名を具体的に埋める。** 「直前のやり取り」だけでは何が出てくるか判断できない。

```
label:       直前のやり取りをそのまま
description: #11 の done-criteria 欠落と CI 未配線の調査結果を、そのまま一覧にする
```

2 つ目が選ばれたら、**何を見たいかを続けて聞く**（その場で `AskUserQuestion` を重ねず、通常の応答で尋ねる）。

**質問を省略してよい場合:**

- 依頼文が対象を名指ししている（「ハーネスの状況を HTML で見せて」「この比較表をブラウザで」）
- 「さっきのページを更新して」など、既存ページの更新が明らかな場合

## 手順

1. `template.html`（このスキルのディレクトリ内）をコピーして中身を差し替える。**デザインは毎回考え直さない。** 確定した見た目なので、そこに内容を流し込む
   ```bash
   D="${XDG_CACHE_HOME:-$HOME/.cache}/claude-view"
   mkdir -p "$D"
   cp ~/dotfiles/claude/skills/html-view/template.html "$D/<slug>.html"
   ```
2. `<slug>` は**話題ごとに安定した名前**（`harness-status.html` など）。同じ話題なら必ず同じ名前を使い回す
3. `view-html "$D/<slug>.html"` で開く

**コードブロックには色を付ける。** `bin/highlight-code` に流し、出力を `<pre><code>` の中に入れる。

```bash
highlight-code --lang terraform < snippet.tf     # 言語名は --list で確認
```

- 色は `--tok-*` トークンで定義済み。`c`（コメント）`s`（文字列）`k`（キーワード）`m`（数値）`n`（名前）`t`（型）`o`（記号）の class が付く
- **言語は生成時に分かっているので明示する。** 未知の言語なら素のまま返るので壊れない
- **インライン `code` には付けない。** 文中の識別子は色を付けると読点のように見える
- コマンドの実行結果・計測値の表は色を付けない。コードではない

**触ったファイルのパスを添える。** どの行がどのファイルの話かは、読者が最初に探す情報。

```html
<div class="files">
  <span><b>src/components/EmpDropdown.vue</b> <span class="at">:118</span></span>
  <span><b>terraform/portal.tf</b></span>
</div>
```

- 置き場所は行を開いた直後、`note` の下。**等幅・小さめ・`--faint`** なので、探せば見つかり、読まなければ邪魔にならない
- リポジトリ相対パスで書く。絶対パスは環境に依存し、他の人が使えない
- 5 件を超えるなら代表 2〜3 件と件数（`他 6 ファイル`）にする。全部並べると本文を押しのける
- 行番号・シンボル名が特定できるなら `at` で添える

`view-html`（`bin/view-html`）は既定ブラウザで開く。**同じファイルを再度渡すと、既存タブを探して再読み込みし前面に出す。** `open` を直に使うと同じ URL でも新しいタブが増え、更新のたびに古いページが並んでどれが最新か分からなくなる。

- 出力は `opened:` / `reloaded:` / `opened (via open):` のいずれか
- ブラウザ未起動・自動化許可なし・非対応ブラウザでは `open` にフォールバックする
- `--print-url` は URL だけ出してブラウザを開かない

## 更新

| 状況 | やること |
|---|---|
| 内容が変わった | **同じファイル名**に書き直して `view-html` を再実行する |
| 別ページとして分けたい | 別のファイル名にする |
| 別セッションから更新 | ファイル名が同じなら、そのまま書き直して `view-html` を再実行する |

保存先を `~/.cache` に置くのは、セッションをまたいでも同じパスを指せるようにするため。scratchpad はセッションごとに変わるので、「さっきのページを更新して」に応えられなくなる。

## 崩してはいけない設計

`template.html` に実装済み。内容に合わせて増減してよいが、以下は変えない。**目への負担を下げるための決定が含まれており、理由を知らないと間違いに見えて「直されてしまう」。**

| 項目 | 決まり | 理由 |
|---|---|---|
| テーマ | **青系ダークを既定にし、`prefers-color-scheme` に追従しない。** ライトは `:root[data-theme="light"]` のトグル時のみ | テーマは決定事項で、OS から継承するものではない |
| 地色 | **純白でも純黒でもない。** 青は地色側に持たせ、文字は中立色に寄せる | 純白は画面の最大輝度。純黒は文字とのコントラストを最大化する。青は焦点が合いにくい（色収差）ので、**発光面**を青くするのは避け、暗い地色として使う |
| 本文の文字色 | **純白・純黒にしない。** 地色とのコントラストを **10〜13:1** に収める（両テーマ） | コントラストは高いほど良いのではない。純黒×純白は 21:1 で、文字が滲んで残像が出る（ハレーション）。AAA の下限 7:1 は超えつつ、負担域に入れない |
| 書体 | **見出しも本文もゴシック体（Hiragino Sans）。明朝体は使わない** | 明朝の細い線は見出しサイズでも痩せて見え、解像に負担がかかる |
| 基準の文字サイズ | **`19px` 以上**、行送り `2`、字間 `.02em` | 文字が大きいほどピント調節の負荷が下がる。行送りを広げると隣の行に視線が落ちて読み直す事故が減る |
| ページ幅 | `76rem` | |
| 文章の行長 | **上限を付けない。** 本文はページ幅いっぱいまで 1 行で流す | 細い柱になって右側が空くのを避ける。行長の唯一の制約はページ幅（`76rem`）側 |
| アニメーション | **`transition` / `animation` を持たせない** | 動きは追視の負担になる。開閉の表示は記号の差し替えで行う |
| 日本語の折り返し | `word-break: auto-phrase` + `line-break: strict` + `.wrap` に `lang="ja"` | 日本語は文字間のほぼどこでも改行できるため、既定では単語の途中で切れる（「が立 / たない」）。文節単位で折り返すには**内容言語の指定が必須** |
| 行の見出し | `.title` は太字（600）で本文より大きく | 行の見出しに相当する要素が本文と同じ太さだと、細く小さく見える |
| 行の構成 | `番号 / タイトル / 状態 / 開閉記号` の 4 カラム。状態は右端で縦に揃える | 走査は縦方向に行われる |
| セクション | `<details>` で包み、`open` 属性を付けない | `summary` 行が唯一の走査面になる |
| 重要度 | `high` / `mid` / `low` クラスで 3px の縦線と状態ラベルに色を付ける | 1px では色が視認できない |
| 補足テキストの色 | 主文字の 1 段下（`--dim`）まで。3 段下げない | 「文字が薄い」の主因は補足テキスト側 |
| 開いた本文 | **地色と別の面にする**（`--raised` の塗り + 1px 罫線）。地色との比は 1.15:1 以上 | 塗りが 1.1:1 程度だと「背景と同色」に見える。重要度の帯を本文の左端まで続けると、どの行を開いているか分かる |

**色を変えたら実測する。** 判定は `bats test/html-view-template.bats` が行う（本文の上下限、地色の輝度、`--dim` の AAA、アクセントと重要度の AA を検査）。手元で 1 組だけ確かめたいときは次を使う。

```bash
python3 -c '
def lum(h):
    h=h.lstrip("#"); c=[int(h[i:i+2],16)/255 for i in (0,2,4)]
    c=[(x/12.92 if x<=0.03928 else ((x+0.055)/1.055)**2.4) for x in c]
    return 0.2126*c[0]+0.7152*c[1]+0.0722*c[2]
def ratio(a,b):
    la,lb=lum(a),lum(b); return (max(la,lb)+0.05)/(min(la,lb)+0.05)
print(round(ratio("#f0eee8","#2c2b31"), 2))'
```

## 図と表の使い分け

**既定を図表側に置く。** 文章に戻すのは、因果・判断・理由を述べるときだけ。下の合図が出たら、まず表か図にできないかを考える。

| 合図 | 変換先 |
|---|---|
| 3 項目以上を並列に並べている | 表（1 列で済むなら箇条書き） |
| 「A は X、B は Y」と対応関係を書いている | 表 |
| 「前は〜、今は〜」と前後を述べている | 表（変更前 / 変更後の 2 列） |
| 「A の後に B」「A が B を止めている」 | 図（`.flow`） |
| 数値が 3 つ以上出てくる | 表 + `class="num"` |
| 「〜の場合は…、〜の場合は…」と条件分岐を書いている | 表（条件 / 結果の 2 列） |
| 階層・入れ子を言葉で説明している | 図（`.flow.down`）または inline SVG |

情報の型ごとの対応は次のとおり。

| 情報の型 | 使うもの | 文章にすると何が起きるか |
|---|---|---|
| 2 軸以上の値（項目 × 属性、変更前 × 変更後） | **表** | 読者が頭の中で表を組み直すことになる |
| 順序・依存・前後関係（A の後に B、A が B を止めている） | **図**（`.flow`） | 形が情報そのものなので、読者に図を描かせることになる |
| 数値の比較 | 表 + `class="num"`（等幅数字で桁を揃える） | 桁が揃わず大小が読めない |
| 状態の良否 | 表のセルに `good` / `warn` / `bad` | 「達成」「未達」の語だけでは走査できない |
| 理由・判断・経緯 | **文章** | 表に押し込むと因果が失われる |
| 箇条書きにできる並列 | 箇条書き | 表にすると 1 列の表になり枠が邪魔をする |

**1 列しかない表を作らない。** それは箇条書きである。**逆に、文章の中で「A は X、B は Y、C は Z」と 3 つ以上並べ始めたら表にする。**

`.flow` は CSS の箱と矢印で、`step` に `done` / `blocked` / `pending` を付けると重要度色が付く。箱で表せない図は **inline SVG** を書く（`svg text` などのスタイルはトークン側で定義済みなのでテーマに追従する）。

**mermaid は使えない。** 外部スクリプトを読み込めないため。図は CSS か inline SVG で描く。

## タイトル

**ユーザーの依頼文をそのまま、または短く言い直したものを `<title>` に書く。** こちらで話題を言い換えて抽象化しない。ユーザー自身の言葉で探せることが目的。更新時にタイトルは変えない。

## URL で共有したいとき（`--share`）

**共有を明示的に頼まれたときだけ** `Artifact` ツールで公開する。ローカルファイルは自分しか開けないため、URL を渡す必要がある場合に限る。公開の前に `artifact-design` skill をロードする。

- 同じ会話なら、**同じ file_path** で再発行すれば URL は変わらない
- 過去の会話で作ったページは `action: "list"` で URL を探し、`url` パラメータに渡す。渡さないと新しい URL が発行されて元のページが取り残される
- `favicon` は必須で、再発行では変えない
- **公開したアカウントでログインしていないと `Page not found` になる。** 複数アカウントを使い分けている場合、どちらで公開したかを伝える

## 制約

- **1 ファイルで自己完結させる。** CSS と JS はインライン、画像は data URI。外部 CDN を参照するとオフラインで壊れ、ローカルページから外部へ通信が漏れる
- 横に広い要素（表・コードブロック・図）は `overflow-x: auto` の入れ物に入れる。本文が横スクロールしてはいけない
- **PII を載せない。** 氏名・社員番号・メール・電話番号はマスキングする。共有した時点で外に出る
- 指定した書体が入っているか確認する。無ければ黙って別の書体に落ちる

## よくある失敗

| 失敗 | 何が起きるか |
|---|---|
| 更新のたびに新しいファイル名を使う | ページが増え、どれが最新か分からなくなる |
| `open` を直に呼ぶ | 同じ URL でもタブが増殖する |
| 保存先を scratchpad にする | 別セッションから同じページを更新できない |
| `prefers-color-scheme` を足す | テーマが OS 設定に乗っ取られ、意図した見た目にならない |
| コントラストを上げれば読みやすいと考える | 純黒×純白は 21:1 でハレーションを起こし、かえって疲れる |
| `open` 属性を付ける | 折りたたみの意味がなくなり、ターミナルと同じ壁になる |
| 本文の隣に中身のないカラムを置く | 文章が細い柱になり、右側が空いて見える |
| 本文に `max-width` を付ける | 幅が余り、文章が細い柱になる |
| 図の矢印を独立した要素で書く | 折り返しで矢印だけが行末に取り残される。矢印は箱側から生成する |
| `lang="ja"` を落とす | 文節での折り返しが効かず、単語の途中で改行される |
| 開閉に `transition` を付ける | 動きを目で追う負担が増える |
| 開いた本文を地色のままにする | どこからどこまでが 1 行の中身か分からない |
| 見出しに明朝体を使う | 線が細く痩せて見える |
| タイトルを話題ごとに言い換える | ユーザーが探せなくなる |
| 頼まれていないのに HTML 化する | 会話の流れが切れる |
| 対象が曖昧なまま作り始める | 見たかったものと違うページができ、作り直しになる |
| 選択肢に「直前のやり取り」とだけ書く | 何が出てくるか判断できないので選べない。話題名を埋める |
| 触ったファイルのパスを書かない | 読者が最初に探す情報が無く、コードに戻れない |
| パスを絶対パスで書く | 環境に依存し、他の人が使えない |
| 共有を頼まれていないのに公開する | 不要な URL が残る |
