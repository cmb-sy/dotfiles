# Artifact View — 使い捨て HTML で見せる

ターミナルのテキストでは読みにくい情報を、その場限りの HTML ページとして出す。同じ話題の情報が更新されたら、**新しいページを作らず同じページを更新する**。

## 発動条件

**明示的に頼まれたときだけ使う。** 長い出力を勝手に HTML 化しない。

| 使う | 使わない |
|---|---|
| 「HTML で見せて」「アーティファクトにして」「ブラウザで見たい」 | 頼まれていない通常の応答 |
| 「見やすくして」「表で見たい」（現在の出力を指して） | 恒久的に残す学習教材 → `learn` |
| 「さっきの◯◯を更新して」（既存ページを指して） | 検証付きの技術メモ → `tech-memo` |
| 既存スキルの長い出力を渡されて可視化を頼まれた | 非エンジニア向けの報告文 → `share-report` |

判断に迷ったら作らない。ユーザーは必要なら明示的に頼む。

## ページを書く前に

1. **`artifact-design` skill をロードする**（必須）。デザインの投資量をタスクに合わせて決めるため。
2. ファイルは scratchpad に置く。話題ごとに**安定したファイル名**を付ける（例: `harness-status.html`）。更新時に同じパスを使えることが、同じ URL を保つ条件になる。

## 構造の規約

**セクションは `<details>` で包み、既定は閉じておく。** `open` 属性を付けない。

```html
<details>
  <summary>
    <span class="id">#11</span>
    <span class="title">done-criteria 11 件が欠落し Audit Gate が実行不能</span>
    <span class="chip stop">憲法と矛盾</span>
  </summary>
  <div class="inner">…</div>
</details>
```

- **`summary` 行が唯一の走査面**になる。識別子・要点・状態チップだけを置き、そこだけ読んで全体像が掴めるようにする
- 開いた状態で置くのは、ページ冒頭の要約とスコア/件数などの一覧だけ
- `summary::-webkit-details-marker { display: none }` で既定の三角を消し、`▸` / `▾` を自前で出すと開閉が分かりやすい
- `summary:focus-visible` に見える輪郭を与える（キーボード操作で位置を失わないため）

`<details>` は HTML 標準で JavaScript 不要。CSP（外部リソースを遮断する仕組み）に触れない。

## タイトルと説明

- **タイトルはユーザーの依頼文をそのまま、または短く言い直したものにする。** `<title>` タグに書く。ユーザーが自分の言葉で探せることが目的なので、こちらで話題を言い換えて抽象化しない
- タイトルは再発行しても変えない。ギャラリーとタブでの同一性が失われる
- `description` パラメータはギャラリーカードの副題。そのページが何かを 1 文で書く
- `favicon` は必須。**再発行では変えない**。ユーザーはタブのアイコンでページを見つける

## 更新

| 状況 | やること |
|---|---|
| 同じ会話で作ったページを更新 | ファイルを編集し、**同じ file_path** で再発行する。URL は変わらない |
| 過去の会話で作ったページを更新 | `action: "list"` で URL を探し、`url` パラメータに渡す |
| 別ページとして分けたい | 別のファイルパスにする（新しい URL が発行される） |

**`url` を渡さずに過去のページを更新しようとすると、新しい URL が発行されて元のページが取り残される。** 「さっきの」「あの」とユーザーが既存ページを指しているときは、必ず `list` で URL を確定してから更新する。

`capabilities` を渡す必要があるとき（データを更新し続ける、閲覧者間で状態を共有する等）は、先に `artifact-capabilities` skill をロードする。再発行時にこのフィールドを省略すると、既存の宣言がそのまま引き継がれる。

## 制約

- **自己完結でなければ動かない。** 外部 CDN のスクリプト・スタイル・フォント・画像はすべて遮断される。CSS と JS はインライン、画像は data URI。mermaid は `<pre class="mermaid">` でネイティブに描画される
- **両テーマを設計する。** `@media (prefers-color-scheme: dark)` に加え、`:root[data-theme="dark"]` / `[data-theme="light"]` を両方向で上書きする（閲覧者のトグルが勝つ必要がある）
- 横に広い要素（表・コードブロック・図）は `overflow-x: auto` の入れ物に入れる。本文が横スクロールしてはいけない
- **PII を載せない。** artifact は既定非公開だが、URL を渡せば共有される。氏名・社員番号・メール・電話番号はマスキングする
- 他人から共有された artifact は読めるが更新できない

## よくある失敗

| 失敗 | 何が起きるか |
|---|---|
| 更新のたびに新しいファイル名を使う | URL が増え、ユーザーがどれが最新か分からなくなる |
| 過去の会話のページを `url` なしで再発行 | 元ページが更新されず、重複ページができる |
| `open` 属性を付ける | 折りたたみの意味がなくなり、ターミナルと同じ壁になる |
| favicon を毎回変える | タブでページを見失う |
| タイトルを話題ごとに言い換える | ギャラリーで探せなくなる |
| 外部 CDN を参照する | CSP に落ちて何も表示されない |
| 依頼されていないのに HTML 化する | 会話の流れが切れ、URL が散らかる |
